# M0 技术验证报告（正式版第一步）

> 日期：2026-11-26 · 对应企划书 §10 M0 · 状态：核心库与 CLI 已落地并通过测试，Tauri 外壳待 MSVC 环境构建

## 1. 本轮目标

按企划书 M0「技术验证」：**Rust 能真实下载并启动原版 Minecraft；微软登录链路可接入；安装必须由用户显式发起**。
本轮完成前两项的核心实现与自动化测试，第三项落实到 CLI 与桌面命令的接口语义。

## 2. 工程结构（本仓库）

```
src-tauri/
├── Cargo.toml                  # Rust workspace（core / downloader / cli）
├── crates/
│   ├── pomelo-core/            # 核心库（无 UI、无 Tauri 依赖，可被 CLI 复用）
│   │   ├── meta.rs             # 版本清单/版本 JSON/inheritsFrom 合并/规则求值/资产索引
│   │   ├── java.rs             # Java 扫描、版本解析、按 MC 版本匹配
│   │   ├── launch.rs           # classpath、参数求值与占位符替换、进程拉起、日志管道
│   │   ├── instance.rs         # 实例存储（每实例独立 .minecraft，版本隔离）
│   │   ├── auth.rs             # 离线 UUID、Microsoft 设备码链路（XBL/XSTS/Minecraft）、账户存储
│   │   └── error.rs
│   ├── pomelo-downloader/      # 官方源/BMCLAPI 镜像重写、并发下载、SHA1 校验、natives 解压
│   └── pomelo-cli/             # CLI：java / versions / install / launch / info
└── app/                        # Tauri 2 桌面外壳（MSVC 构建）
    ├── Cargo.toml · tauri.conf.json · capabilities/
    └── src/main.rs             # system_info / list_java / list_instances / install_instance / launch_instance / read_log
```

前端（`src/`）保持浏览器 DEMO 可运行；新增 `src/desktop.ts` 探测 Tauri：
- 桌面端：设置页「桌面核心」显示核心连接、数据目录、Java 列表，标题栏按钮调用原生窗口 API。
- 浏览器：保持 mock 演示，并提示桌面版启动命令。

## 3. 已实现的核心能力

| 能力 | 说明 |
| --- | --- |
| 版本解析 | version_manifest_v2 → 版本 JSON → `inheritsFrom` 链合并（库去重、参数追加、mainClass 覆盖、jar_id 取根版本） |
| 规则求值 | os.name / os.arch / features 规则；无规则=允许，最后匹配项生效 |
| 类路径 | 规则过滤库 + 客户端 jar，Windows `;` / Unix `:` |
| 参数替换 | `${auth_player_name}` `${auth_uuid}` `${auth_access_token}` `${game_directory}` `${assets_root}` `${assets_index_name}` `${natives_directory}` `${classpath}` 等全量替换 |
| 下载 | 官方 ↔ BMCLAPI 自动重写（清单/版本 JSON/对象/资产/maven），失败回退，SHA1 校验，已存在跳过 |
| natives | 按平台 classifier 解压（跳过 META-INF，拒绝路径穿越） |
| Java | PATH/JAVA_HOME/常见安装目录扫描，解析版本号，按 MC 版本匹配（1.16-→8 / 1.17→16 / 1.18–1.20.4→17 / 1.20.5+→21） |
| 实例 | 独立 `.minecraft`（版本隔离）、instance.json 元数据、已安装校验 |
| 账户 | 离线 UUID（MD5 + v3 位）、Microsoft 设备码 → XBL → XSTS → Minecraft 令牌 → 档案 |
| 启动 | 参数组装、工作目录、stdout/stderr 追加到 `logs/latest.log` |

## 4. CLI 用法（可直接体验真实安装/启动）

```bash
cd src-tauri

# 1) 查看本机 Java（以及所需版本映射）
cargo run -p pomelo-cli -- java

# 2) 查看可用版本（加 --mirror 使用 BMCLAPI 清单）
cargo run -p pomelo-cli -- versions --kind release --limit 10 --mirror

# 3) 安装（显式执行才下载；创建新实例并隔离目录）
cargo run -p pomelo-cli -- install 1.21.4 --name 我的原版 --mirror
#   数据目录默认 %APPDATA%/PomeloLauncher；可加 --root D:\mc-data

# 4) 查看实例
cargo run -p pomelo-cli -- info 我的原版

# 5) 启动（离线账户；--dry-run 只打印命令）
cargo run -p pomelo-cli -- launch 我的原版 --name Steve --memory 4096
```

产物目录（每实例隔离）：

```
<root>/instances/<id>/.minecraft/
├── versions/1.21.4/{1.21.4.json, 1.21.4.jar, natives/}
├── libraries/...
├── assets/{indexes,objects}/...
└── logs/latest.log
```

| 真实启动游戏 | 未在本轮自动执行（会打开游戏窗口）。用户可运行：`pomelo launch M0-Verify --name Steve --root D:/Project/PomeloLauncher/.m0-data` |

过程中修复的真实缺陷（均已回归测试覆盖）：
1. `select_java` 生命周期签名错误；
2. 库去重 key 未包含 classifier，导致原版 lwjgl 主体 jar 被 natives 变体覆盖；
3. 现代版本 JSON 的 natives 变体需要按架构后缀（`-arm64` / `-x86`）过滤；
4. BMCLAPI 清单/资产索引偶发 DNS 失败 → 增加镜像→官方自动回退。

## 6. 桌面版构建

> **本机实测（2026-11-26）**：在没有 Visual Studio / MSVC 的环境中，使用 rustup GNU 工具链（`stable-x86_64-pc-windows-gnu`，gcc 链接）即可完成 Tauri 2 桌面版的 `cargo build` 并正常运行（窗口、IPC、WebView2 均正常）。产物：
> - `src-tauri/app/target/debug/pomelo-launcher.exe`
> - `src-tauri/app/target/release/pomelo-launcher.exe`（release）
>
> 说明：Tauri 官方推荐 MSVC；打包安装器（NSIS/MSI）与 CI 仍建议使用 MSVC + `cargo-tauri`。GNU 路径作为本机无 MSVC 时的可行替代，已实测通过（debug/release 编译）。

Windows 官方支持路径是 MSVC 工具链：

```powershell
# 前置：VS Build Tools（C++ 桌面开发）、WebView2 Runtime、Rust MSVC toolchain、Tauri CLI
rustup default stable-x86_64-pc-windows-msvc
cargo install tauri-cli --version "^2"
cd src-tauri/app
cargo tauri dev     # 开发
cargo tauri build   # 打包 NSIS/MSI
```

> 首次构建会拉取 Tauri 依赖（数分钟）。窗口使用自定义标题栏（`decorations: false` + `data-tauri-drag-region`）。

## 7. 已知边界（M0）

- 仅原版启动；Forge/Fabric 的 inheritsFrom 安装器与 OptiFine 在 M1 接入（核心合并逻辑已就绪）。
- Microsoft 登录为实验性实现，需要一个自备的 Azure 应用客户端 ID；未做令牌刷新与密钥环存储（M0 明文账户文件，M1 迁移 keyring）。
- 下载为文件级并发（默认 8）；分片下载、断点续传、进度事件细化在 M1。
- 桌面端尚未把实例数据接入 store（当前仅提供系统信息/Java/实例列表/安装/启动命令）；M1 切换数据源并补齐安装进度 UI。
- 崩溃规则引擎、资源中心接入（Modrinth/CF）、整合包导入导出在 M1/M2。
