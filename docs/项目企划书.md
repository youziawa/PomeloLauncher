### 1.1 基本信息

| 项 | 内容 |
| --- | --- |
| 项目名 | **PomeloLauncher**（中文名：柚子启动器） |
| 仓库目录 | `D:\Project\PomeloLauncher` |
| 开源许可 | **Apache-2.0**（宽松、可商用、专利授权友好，与 GPL 系竞品形成差异化） |
| 目标平台 | Windows 10+（x64 / ARM64）、macOS 12+（Intel / Apple Silicon）、Linux（x64 / ARM64，主流发行版） |
| 产品形态 | 桌面 GUI 启动器 + 可选 CLI；安装版与便携版（绿色单目录）双形态 |
| 核心受众 | ① 新手玩家（零配置开箱即玩）② 整合包/模组玩家（高效管理）③ 服主与开发者（CLI / 深度链接 / 可脚本化） |
| 品牌意象 | 柚子：清新、圆润、剥开即食 → 对应"清新配色、圆角卡片、开箱即玩"的产品气质 |

### 1.2 为什么要做这个启动器（市场空隙）

调研四大主流启动器后（详见第 2 章），我们观察到以下空隙：

1. **宽松开源许可的空位**：HMCL / SJMCL 为 GPLv3（附加改名条款），PCL 为自定义有限许可（非 OSI 开源），BakaXL 本体闭源。社区缺少一个 **Apache-2.0 / MIT 级宽松许可、可自由二次开发与商用集成** 的现代启动器。
2. **"全功能"与"轻量"难以兼得**：HMCL 功能最全但 JVM 内存 400–530MB；PCL2 体积极小（约 2.7MB）但仅限 Windows 且技术栈（VB.NET）维护性差；SJMCL 证明了 Tauri 路线可以兼得，但项目尚年轻、部分功能仍在补全。
3. **行业不确定性带来的信任需求**：PCL 于 2026-10 宣布移除 MC 下载功能、MCBBS 于 2024 闭站、BakaXL 闭源混淆引发杀软误报——玩家需要一个**代码透明、下载链路合规清晰、不依赖单一社区站点**的启动器。
4. **新手体验仍有痛点**：微软登录国内网络不稳、报错误导（如"未购买"实为未设昵称）、版本隔离令新手困惑、缺前置模组报错高发——这些都是可以用产品设计直接解决的。

### 1.3 核心价值主张

> **功能全面 × 轻盈如柚 × 清新易用**

- **全**：覆盖版本/模组加载器/整合包/资源/账户/Java/崩溃分析/联机的完整生命周期。
- **轻**：安装包 ≤ 20MB、冷启动 ≤ 1.5s、空闲内存 ≤ 150MB、游戏启动后可自动退出释放资源。
- **美**：原创"清新柚园（Pomelo Garden）"设计语言，深浅双主题、壁纸系统、克制动效。
- **易**：首次运行 3 步向导即可开玩；崩溃自动诊断并给出人话修复建议；所有报错可一键导出求助包。

### 2.3 十条核心经验（直接指导本项目设计）

1. **下载体系是生命线**（HMCL/PCL）：多镜像源 + 失效自动回退 + 断点续传 + SHA1 校验 + 并发/代理可调，是国内体验的底线。MCBBS 闭站、PCL 停下载证明：**不能把命脉押在单一社区源上**，官方源必须始终可用。
2. **崩溃分析是口碑放大器**（PCL 招牌）：规则驱动（致命→主要→次要）+ 堆栈回溯定位肇事 Mod + "人话"修复建议，能极大降低社区求助成本。规则库应做成**可社区贡献的数据文件**而非硬编码。
3. **版本隔离 + 实例模型是模组玩家刚需**（四家全有）：但 HMCL 文档专门提示隔离会改变游戏目录令新手困惑 → 默认开启隔离，但 UI 上必须把"文件在哪"讲清楚（一键打开目录）。
4. **Java 全自动是新手门槛的钥匙**（HMCL/SJMCL）：扫描 + 按 MC 版本自动匹配 + 自动下载（Mojang / Foojay 双源）+ 内存自动分配，做到"用户永远不需要理解 Java"。
5. **Tauri 路线已被双重验证**（SJMCL 1.4 稳定版 + BakaXL 4 重写）：系统 WebView 带来 16–29MB 安装包与低内存，Rust 后端天然适合下载/启动/校验这类 IO 密集核心。**这是"全功能 × 轻量"兼得的当前最优解**。
6. **整合包导入导出 + 迁移成本决定用户流入**（SJMCL 支持从 HMCL/MultiMC 导入账户与认证服务器）：支持主流格式互导、支持从其他启动器"搬家"，是冷启动获客的关键。
7. **本土化细节值钱**（SJMCL 双语搜索 + MCMod 中文译名缓存；BakaXL 集成 MC百科）：中文模组名、中文报错、国内镜像默认优先，是国内启动器的护城河。
8. **个性化是留存与传播点**（PCL 自定义主页 / BakaXL 主题生态 / HMCL 主题包 + 莫奈取色）：壁纸、主题色、深浅色、动效开关要一等公民化；但 PCL"赞助解锁主题色"引发过争议 → **个性化功能全部免费开放**。
9. **报错要"可行动"**（HMCL issue #3330："未购买"实为未设昵称）：每条错误必须附带原因解释 + 下一步操作按钮；崩溃报告打包时**自动打码敏感信息**（BakaXL 4 的做法）。
10. **透明与合规是长期信任**（BakaXL 闭源混淆 → 杀软误报 → 官方被迫专门发文解释）：开源 + 代码签名 + 清晰的下载链路说明 + 默认关闭遥测，能避免大量信任成本。

### 2.4 竞品教训（本项目明确规避）

| 教训 | 来源 | 本项目对策 |
| --- | --- | --- |
| 大版本重写导致功能断档（成就系统未迁移、4.0 长期预览） | BakaXL 3→4 | 核心与 UI 分层，核心库独立 crate 可复用；重写只换壳不换核 |

## 3. 产品定位与设计原则

### 3.1 定位矩阵

```
                 功能全面
                    ▲
        HMCL ●      │      ● PomeloLauncher（目标位置）
                    │
  重 ───────────────┼─────────────── 轻
                    │   ● SJMCL
        BakaXL ●    │      ● PCL2（轻但仅 Win/功能收敛）
                    ▼
                 功能收敛
```

### 3.2 五条设计原则

1. **三步开玩（Zero-to-Play ≤ 3 步）**：首次运行向导 = ① 登录（或离线体验）→ ② 选版本（默认最新正式版，自动装 Java）→ ③ 点启动。其余一切默认值兜底。
2. **渐进披露（Progressive Disclosure）**：首页只有"实例 + 账户 + 启动"；高级选项（JVM 参数、GC、代理、隔离策略）折叠在实例设置深处，但**永远可达**。
3. **每个错误都有出口**：任何失败界面必须包含「为什么」「怎么办」「一键导出求助包」三要素。
4. **轻量是硬指标不是口号**：体积/启动/内存写入验收标准（§8），CI 每次构建回归。
5. **默认安全与隐私**：全下载 SHA1/SHA256 校验、令牌存系统密钥环、零默认遥测、崩溃报告自动脱敏。

## 4. 技术选型（语言与框架）

### 4.1 候选方案对比

| 方案 | 代表 | 体积 | 内存 | 跨平台 | 生态/许可 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **Tauri 2 + Rust + Web 前端** | SJMCL、BakaXL 4 | ★★★★★（16–29MB） | ★★★★★ | Win/mac/Linux | MIT/Apache 双许可，生态宽松 | ✅ **推荐** |
| .NET 8/10 + Avalonia | PCL-CE | ★★★（单文件 ≈ 23MB + 运行时） | ★★★★ | 三平台 | MIT | 备选：C# 团队熟悉时可选，但需捆绑运行时或依赖用户安装 |
| Java + JavaFX | HMCL | ★★★★（jar ≈ 12MB 但需 JRE） | ★★（400MB+） | 最广（含 FreeBSD/龙芯） | GPL 系竞品多 | ❌ 内存与冷启动不达标 |
| Electron + TS | （官方启动器等） | ★（80–150MB） | ★★ | 三平台 | MIT | ❌ 与"轻量"定位直接冲突 |
| Qt 6 / C++ | （部分小众启动器） | ★★★★ | ★★★★★ | 三平台 | LGPL/商业双许可，UI 开发效率低 | ❌ 开发效率与人才池劣势 |
| VB.NET + WPF | PCL2 | ★★★★★（2.7MB） | ★★★★ | 仅 Win | 技术栈老化 | ❌ 维护性差，社区贡献门槛高 |

### 4.2 推荐技术栈（定案）

**总体：Tauri 2（Rust 后端）+ React 18 + TypeScript（前端），Apache-2.0 开源。**

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 应用框架 | **Tauri 2.x** | 系统 WebView（WebView2 / WKWebView / WebKitGTK），不捆绑 Chromium；SJMCL 与 BakaXL 4 已验证该路线可达 16–29MB；内置 updater / 深度链接 / 系统托盘 / 单实例锁 |
| 核心语言 | **Rust（edition 2021+）** | 内存安全 + 零成本抽象；下载/校验/进程管理 IO 密集场景性能充裕；核心编译为独立 crate `pomelo-core`，与 UI 解耦，可被 CLI 复用 |
| 异步运行时 | tokio + reqwest（rustls-tls） | 全异步下载引擎；rustls 避免 OpenSSL 交叉编译地狱 |
| 前端框架 | **React 18 + TypeScript 5 + Vite** | 人才池最大、组件生态最全；相比 SJMCL 的 Next.js，纯 Vite SPA 更轻（启动器无需 SSR/路由服务端） |
| UI 组件 | **Radix UI（无样式原语）+ Tailwind CSS 4** | 自建设计系统"Pomelo Garden"，不依赖重型组件库的默认观感；无障碍由 Radix 原语保证 |
| 动效 | **Motion（framer-motion）** | 声明式过渡；全局"减少动效"开关一键降级 |
| 状态/数据 | Zustand（客户端状态）+ TanStack Query（异步资源缓存） | 实例列表/下载任务/资源搜索天然适合 query 缓存模型 |
| 本地存储 | SQLite（rusqlite，WAL 模式）+ JSON 配置文件 | 实例/账户/资源索引入库；人类可读配置用 JSON（便于手改与版本迁移） |
| 国际化 | i18next + react-i18next | 首发 zh-Hans / zh-Hant / en，社区众包扩展 |
| 皮肤预览 | skinview3d | 与 SJMCL 同款成熟方案（MIT） |
| 虚拟列表 | @tanstack/react-virtual | 万级模组/资源列表不卡顿 |
| NBT 解析 | quartz_nbt（Rust） | 存档 level.dat / 服务器列表解析 |
| 服务器探测 | 自研 Server List Ping 协议（Rust，tokio） | 延迟/在线人数/图标，无需第三方依赖 |
| 密钥存储 | keyring crate（Windows Credential Manager / macOS Keychain / Secret Service） | 微软刷新令牌与第三方凭据不落明文 |
| 崩溃规则库 | TOML 数据文件 + Rust 规则引擎 | 社区可 PR 贡献规则，无需改代码 |
| 构建/分发 | GitHub Actions 三平台矩阵；NSIS / MSI（Win）、dmg（mac）、deb / rpm / AppImage（Linux）；winget / Homebrew / AUR 后续接入 | 参考 SJMCL 多渠道分发经验 |

### 4.3 关键依赖与复用策略（许可安全）

- **只借鉴思想与公开协议，不复制 GPL 代码**：HMCL（GPLv3+附加）、SJMCL（GPLv3+附加）的实现一律 clean-room 重写；Minecraft 启动协议本身（version JSON、asset index、launch 参数）是公开事实，不受 GPL 约束。
- **authlib-injector**：以独立 `-javaagent` jar 注入**游戏进程**（启动器仅负责下载与传参），启动器本体不构成其衍生作品；其许可证条款需在 M0 阶段核实归档（见 §9.4）。
- **LWJGL Unsafe Agent**（Glavo 作品，SJMCL 亦复用）：用于修复受影响版本的 LWJGL 性能问题；许可证核实后以同样"外部 agent"方式集成。
- **PCL / BakaXL**：前者自定义许可、后者闭源，**零代码接触**，仅参考公开的功能设计与交互理念。
- 所有第三方 crate / npm 依赖建立 `LICENSES.md` 清单，CI 用 `cargo-deny` + `license-checker` 拦截 GPL/AGPL 静态链接进入本体。

## 6. UI / UX 设计规范

### 6.1 设计语言：Pomelo Garden（清新柚园）

**关键词**：清新、圆润、通透、克制。区别于 PCL 的"蓝色科技感"、BakaXL 的"Metro 磁贴"、HMCL 的"Material 3"，建立原创识别度。

#### 色彩令牌（Design Tokens）

| 令牌 | 浅色模式 | 深色模式 | 用途 |
| --- | --- | --- | --- |
| `--primary`（柚叶绿） | `#7BA23F` | `#A8C66C` | 主按钮、选中态、品牌识别 |
| `--primary-soft` | `#EEF4E2` | `#2A331F` | 选中背景、标签底色 |
| `--accent`（柚瓤黄） | `#F2C14E` | `#E8B84B` | 高亮、进度、徽标点缀 |
| `--bg`（奶油白 / 炭绿） | `#FAF9F4` | `#191C16` | 窗口底色 |
| `--surface` | `#FFFFFF` | `#232720` | 卡片 |
| `--text` | `#2B2E26` | `#E8EAE3` | 正文 |
| `--text-muted` | `#7A7E72` | `#9BA093` | 次要信息 |

### 6.4 关键用户旅程

**旅程 A：新手第一次玩（目标 ≤ 3 步、≤ 5 分钟）**
1. 欢迎页 → 选择"正版登录"（设备码，手机扫码即可）或"先离线试试"。
2. 推荐最新正式版 → **由用户确认后**下载游戏文件（Java 运行时自动准备）→ 下载完成，首页大按钮点亮。
3. 点击启动 → 游戏出现。启动器按默认策略隐藏到托盘。

**旅程 B：整合包玩家**
拖入 .mrpack → 解析预览（名称/版本/模组数/缺失项）→ 确认安装 → 自动补全 → 实例卡片出现在首页 → 启动。全程无需理解 Java/隔离/内存。

**旅程 C：游戏崩溃**
崩溃弹窗自动出现 → 人话诊断 + "禁用肇事模组并重试"按钮 → 若未解决，"导出求助包"（已脱敏）→ 粘贴到社区/AI 求助。

### 6.5 文案规范

- 中文文案口语化、无术语堆砌；错误文案三段式：**发生了什么 → 为什么 → 现在怎么办**。
- 禁止误导性报错（吸取 HMCL #3330 教训）：错误码与真实原因一一对应，登录失败细分"网络超时 / 未购买游戏 / 未设置昵称 / 令牌过期"。
- 所有英文术语首次出现附中文注释（如 "快照（Snapshot，测试版）"）。

## 7. 系统架构设计

### 7.1 分层架构

```
┌─────────────────────────────────────────────────────┐
│  前端 UI（React + TS，WebView 内）                    │
│  pages / features / components / design-tokens       │
│  Zustand（状态） TanStack Query（异步缓存） i18next    │
└───────────────────────┬─────────────────────────────┘
                        │ Tauri invoke / event（IPC，类型化契约）
┌───────────────────────┴─────────────────────────────┐
│  pomelo-core（Rust 库 crate，平台无关，可独立测试）     │
│  ┌──────────┬──────────┬──────────┬──────────┐      │
│  │ account  │ instance │ download │  java    │      │
│  │ 微软/离线 │ 版本解析  │ 多源调度  │ 扫描/下载 │      │
│  │ /injector│ 隔离/迁移 │ 分片/校验 │ 匹配     │      │
│  ├──────────┼──────────┼──────────┼──────────┤      │
│  │ launch   │ modpack  │ resource │  crash   │      │
│  │ 流水线    │ 导入/导出 │ MR/CF API│ 规则引擎  │      │
│  │ 进程守护  │ 依赖解析  │ 译名缓存  │ 脱敏打包  │      │
│  └──────────┴──────────┴──────────┴──────────┘      │
│  公共层：config / storage(SQLite+JSON) / net(reqwest) │
│         / security(keyring) / telemetry(opt-in)      │
└───────────────────────┬─────────────────────────────┘
                        │
┌───────────────────────┴─────────────────────────────┐
│  src-tauri 壳：窗口/托盘/深度链接/updater/单实例锁       │

└─────────────────────────────────────────────────────┘
```

**要点**：
- `pomelo-core` 不依赖 Tauri，纯 Rust 库 → 单元测试可覆盖启动流水线/解析器/规则引擎；未来 CLI、服务端工具直接复用（规避 BakaXL"重写即断档"教训）。
- IPC 契约用 TypeScript 类型生成（ts-rs / specta），前后端类型同源，杜绝接口漂移。
- 下载引擎独立 crate `pomelo-downloader`：任务队列 + 源调度器 + 分片器 + 校验器，事件总线向前端推进度。

### 7.4 启动流水线（核心时序）

```
点击启动
 → preflight（Java 匹配 / 内存 / 前置模组 / 资产完整性 / 账户令牌有效性）
 → 解析 version JSON（含继承链：Forge/Fabric 的 inheritsFrom）
 → 构建 classpath + natives 解压目录
 → 组装 JVM 参数（-Xmx / GC / -javaagent:authlib-injector / LWJGL agent / 用户自定义）
 → 组装游戏参数（--accessToken 注入，日志中自动打码）
 → spawn 子进程（工作目录 = 实例游戏目录）
 → 日志泵（stdout/stderr → 前端实时流 + latest.log 落盘）
 → 退出监听：正常退出 → 状态回收；异常退出 → 崩溃捕获 → 规则诊断 → 弹窗
```

- **分支**：trunk-based，短生命周期 feature 分支 + PR 审查；Conventional Commits。
- **测试**：Rust 单元/集成测试（核心库覆盖率目标 ≥ 70%）；前端组件测试（Vitest）+ E2E（Playwright，关键旅程 A/B/C）；**Unicode/中文路径/空格路径专项测试**（BakaXL 教训）；启动冒烟测试（三平台 CI 真启动 MC 到标题界面）。

- **发布**：SemVer；stable/beta 双通道；更新签名；发布说明中英双语；GitHub Release + 官网 + 镜像。
- **文档**：`docs/` 内架构决策记录（ADR）、合规清单、用户文档；README 中英双语。
